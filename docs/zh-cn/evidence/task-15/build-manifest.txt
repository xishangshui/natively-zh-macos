已知限制
========

1. 可执行文件的嵌入元数据仍是 Electron 默认值
   ---------------------------------------------
   release\win-unpacked\Natively ZH.exe 的版本资源显示：
       FileDescription = Electron
       ProductName     = Electron
       FileVersion     = 33.4.11
   而不是 Natively ZH / 2.7.0-zh.1。

   原因：本次打包用 --config.win.signAndEditExecutable=false 跳过了
   签名与 rcedit 工具链。electron-builder 把 rcedit 放在 winCodeSign
   压缩包里，而该包内含 macOS 的符号链接
   （darwin/10.12/lib/libcrypto.dylib 等）。在 Windows 上创建符号链接
   需要 SeCreateSymbolicLinkPrivilege——默认只授予管理员，或在开启
   「开发者模式」后授予普通用户。本机两者都不满足，已实测确认：

       New-Item -ItemType SymbolicLink ...
       → Administrator privilege required for this operation.

   注意 winCodeSign 的解包目录名每次运行都是随机数，所以「预先手动解包
   并跳过 darwin」的绕法无效——下一次运行会换一个新目录重新解包。

   影响范围：仅限 exe 的图标与版本资源。安装包本身的产品名、快捷方式名、
   安装目录选择、appId 与用户数据隔离都正常（见上方「安装包身份」）。

   修复方式（二选一，都需要一次性的管理员操作）：
     a) 用管理员权限的终端跑一次 npx electron-builder --win nsis --x64
        （不加 signAndEditExecutable=false）
     b) 打开 Windows「开发者模式」，之后普通权限即可创建符号链接，
        再按 (a) 重跑

   本构建**没有**做代码签名，这符合设计规格 12.2 的要求：
   不得伪装成官方签名发行版。

2. 上游 package.json 有一处失效的依赖别名（已修）
   -----------------------------------------------
   基线的 dependencies 里有：
       "react-query": "@tanstack/react-query@^5.100.10"
   缺少 npm 别名必需的 npm: 前缀，因此 npm 把它当成本地链接
   （lockfile 里是 "link": true），实际目录从未生成。
   electron-builder 扫描 node modules 时对这个悬空链接直接报
   ENOENT 并中止打包。

   全仓库只有 src/App.tsx 从 @tanstack/react-query 导入，
   没有任何代码 import 'react-query'。因此该别名是死代码，
   已删除并同步 lockfile。这不属于本地化改动，但它阻塞了交付物，
   所以一并修掉并在此记录。

3. C 盘余量偏低
   -------------
   打包时 C 盘仅剩 2.1 GB。已把 TEMP/TMP/ELECTRON_BUILDER_CACHE
   全部指向 D:\zh-build-temp 才完成构建。后续重跑请沿用同样设置。
